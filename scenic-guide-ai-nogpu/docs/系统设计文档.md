# 景区导览服务AI数字人系统 - 系统设计文档

## 1. 项目概述

### 1.1 项目背景
随着景区数字化转型加速，传统人工导览面临成本高、覆盖范围有限、服务质量参差不齐等挑战。本系统利用多模态大模型、RAG知识库和数字人技术，构建一套智能化、沉浸式的景区导览服务系统，实现7×24小时无间断、高质量的景区讲解服务。

### 1.2 系统目标
- **准确性**：景区事实问答准确率 ≥ 90%（RAG知识库保障）
- **实时性**：语音交互整体延迟 < 3秒
- **易用性**：多端统一体验，零学习成本
- **可扩展性**：支持多景区、多语言、多形象扩展

### 1.3 技术亮点
1. **多模态交互**：语音+文字双模态输入，TTS 自然语音输出
2. **RAG 景区知识库**：基于 Chroma 向量数据库，精准检索景区知识
3. **⭐ AI 数字人（核心）**：基于 SadTalker 的音频驱动口型同步技术，生成逼真数字人讲解视频——这是本系统区别于传统 TTS 语音导游的本质差异
4. **GPS 智能触发**：靠近景点自动触发语音讲解
5. **情感分析**：实时分析游客情绪，优化服务质量
6. **多形象切换**：Live2D 轻量动画 / Q 版卡通 / SadTalker 写实数字人，三种形象类型一键切换，适配不同景区风格与硬件条件

## 3. 模块设计

### 3.1 后端模块

#### 3.1.1 RAG知识库服务（rag_service.py）
- **文档处理**：支持PDF/Word/TXT/Markdown自动解析
- **智能切片**：按语义边界切片（chunk_size=500，overlap=50）
- **向量化**：使用text-embedding-ada-002或本地bge-m3模型
- **检索策略**：混合检索（向量相似度 + BM25关键词匹配）
- **精度优化**：重排序（Rerank）+ 相关性阈值过滤

#### 3.1.2 AI对话服务（ai_service.py）
- **多轮对话**：维护会话上下文（最近10轮）
- **景区专属Prompt**：系统提示词注入景区身份和知识
- **意图分类**：路线推荐、景点介绍、服务查询等
- **情感分析**：基于大模型分析游客情绪（积极/中性/消极）

#### 3.1.3 语音服务（voice_service.py）
- **STT**：Whisper medium模型，中文优化
- **TTS**：ParaTTS API（主）+ Edge-TTS（备用）
- **延迟优化**：异步并发处理，流式输出

#### 3.1.4 ⭐ 数字人服务（digital_human_service.py）— 核心组件

数字人服务是本系统的核心技术壁垒，负责将 TTS 生成的语音转化为**口型同步、表情逼真**的数字人讲解视频，让游客看到的是一个"会说话、有表情"的虚拟导游，而非冷冰冰的语音播报。

**三种形象模式**：

| 模式 | 驱动方式 | 视觉效果 | 硬件要求 | 适用场景 |
|------|---------|---------|---------|---------|
| **SadTalker 写实** | 音频驱动 3DMM 口型同步 | 逼真数字人，口型+表情完美同步 | GPU (RTX 3060+) | 本地部署 / GPU 服务器 |
| **Live2D 轻量** | 2D 骨骼动画 + TTS 音频 | 二次元漫画风，自然流畅 | CPU | 所有场景 |
| **Q 版卡通** | 静态图 + CSS 动画 + TTS 音频 | 卡通萌系，亲和有趣 | CPU | 年轻游客 / 亲子景区 |

**SadTalker 工作流**：

```
┌─────────────────┐     ┌──────────────────┐
│  参考图像          │     │  TTS 生成的音频     │
│  (数字人形象照)     │     │  (讲解语音 .wav)    │
└────────┬────────┘     └────────┬─────────┘
         │                       │
         ▼                       ▼
  3D 人脸重建               音频特征提取
  (3DMM 参数拟合)           (唇音对齐模型)
         │                       │
         └───────────┬───────────┘
                     ▼
              ┌──────────────┐
              │  面部动画合成   │
              │  口型 + 表情    │
              │  + 头部姿态     │
              └──────┬───────┘
                     ▼
              ┌──────────────┐
              │  GFPGAN 增强   │
              │  超分辨率输出   │
              │  512×512 mp4  │
              └──────────────┘
```

**关键设计决策**：

1. **视频预生成 + 缓存策略**: 开场白视频(opening.mp4)和待机循环视频(idle_01~05.mp4)预先生成并缓存。游客提问时直接播放缓存视频，避免等待 SadTalker 实时生成(3–8 秒延迟)。讲解结束后自动切回待机视频循环。

2. **渐进式降级**: 
   - 有 GPU → SadTalker 实时生成(完整数字人体验)
   - 无 GPU + 有预生成视频 → 播放缓存视频(TTS 音频叠加静态图)
   - 无 GPU 且无预生成视频 → Live2D 二维动画降级(保证可用)

3. **视频目录挂载**: 预生成视频存储在 Docker 命名卷 `backend_videos` 中，通过环境变量 `SADTALKER_VIDEOS_DIR=/app/videos` 指定。后端 `/sadtalker-videos/` 路由直接挂载该目录，nginx 反向代理配合 7 天浏览器缓存。

4. **SadTalker 开关**: 管理后台可配置 `sadtalker_enabled`，前端根据此值决定展示模式。云服务器设为 `false` 时，系统自动使用预生成视频播放模式，生成新视频的接口返回 404。

### 3.2 前端模块

#### 3.2.1 手机APP端
- **首页**：景区概览、快捷入口、GPS位置展示
- **导览页**：数字人展示、语音/文字交互、字幕展示

## 4. 数据库设计

### 4.1 MySQL 表结构

```sql
-- 景点信息表
CREATE TABLE scenic_spots (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    category VARCHAR(50),
    description TEXT,
    guide_text TEXT,             -- AI讲解词
    lat DECIMAL(10,6),           -- GPS纬度
    lng DECIMAL(10,6),           -- GPS经度
    trigger_radius INT DEFAULT 100,  -- 触发半径(米)
    open_time VARCHAR(50),
    price VARCHAR(50),
    icon VARCHAR(20),
    is_open TINYINT DEFAULT 1,
    created_at DATETIME DEFAULT NOW()
);

-- 对话会话表
CREATE TABLE chat_sessions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    session_id VARCHAR(64) UNIQUE,
    user_id VARCHAR(64),
    source ENUM('app','kiosk','web'),
    spot_id INT,
    started_at DATETIME DEFAULT NOW(),
    ended_at DATETIME
);

-- 对话消息表
CREATE TABLE chat_messages (
    id INT AUTO_INCREMENT PRIMARY KEY,
    session_id VARCHAR(64),
    role ENUM('user','assistant'),
    content TEXT,
    sentiment ENUM('positive','neutral','negative'),
    response_time_ms INT,         -- 响应时间(毫秒)
    rag_used TINYINT DEFAULT 0,   -- 是否使用RAG
    rag_sources JSON,             -- 引用的知识库来源
    created_at DATETIME DEFAULT NOW(),
    INDEX idx_session (session_id),
    INDEX idx_created (created_at)
);

-- 知识库文档表
CREATE TABLE knowledge_documents (
    id INT AUTO_INCREMENT PRIMARY KEY,
    filename VARCHAR(255),
    file_path VARCHAR(500),
    file_type VARCHAR(20),
    file_size VARCHAR(20),
    category VARCHAR(50),
    chunk_count INT DEFAULT 0,
    status ENUM('pending','processing','indexed','failed') DEFAULT 'pending',
    created_at DATETIME DEFAULT NOW()
);

-- FAQ表
CREATE TABLE faqs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    category VARCHAR(50),
    hit_count INT DEFAULT 0,
    created_at DATETIME DEFAULT NOW()
);

-- 数字人配置表
CREATE TABLE avatar_configs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    avatar_name VARCHAR(50),
    voice VARCHAR(50),
    speed FLOAT DEFAULT 1.0,
    pitch INT DEFAULT 0,
    volume INT DEFAULT 80,
    style VARCHAR(50),
    driver VARCHAR(50),
    greeting TEXT,
    farewell TEXT,
    updated_at DATETIME DEFAULT NOW()
);
```

- **Embedding维度**：1536（ada-002）或 768（bge-m3）
- **元数据字段**：`source_file`, `category`, `chunk_index`, `spot_id`

## 6. 性能设计

### 6.1 延迟优化策略

| 环节 | 目标延迟 | 优化方案 |
|------|---------|---------|
| 语音识别 | < 500ms | Whisper 并发处理，GPU 加速 |
| RAG 检索 | < 200ms | Chroma 内存模式，HNSW 索引 |
| 大模型推理 | < 1500ms | 流式输出，温度控制 |
| TTS 合成 | < 300ms | 预热连接池，边生成边播放 |
| **SadTalker 视频生成** | **< 5000ms** | **预生成+缓存策略，GPU (RTX 3060+) 加速** |
| 预生成视频播放 | < 500ms | 浏览器缓存 + nginx 7 天缓存 |
| **总计（预生成模式）** | **< 3000ms** | 并行处理流水线 |
| **总计（实时生成模式）** | **< 8000ms** | 含 SadTalker 推理，GPU 加速 |

### 6.2 并发设计
- **Worker进程**：4个uvicorn worker
- **异步处理**：所有IO操作使用async/await
- **连接池**：数据库连接池（最大20个）
- **缓存策略**：Redis缓存热点问答（TTL=3600s）

## 7. 安全设计

- **API鉴权**：JWT Bearer Token，24小时有效期
- **速率限制**：每IP每分钟最多60次请求
- **输入过滤**：XSS防护，SQL注入防护
- **文件上传**：类型白名单，大小限制50MB，病毒扫描
- **数据脱敏**：用户个人信息加密存储，日志脱敏

## 8. 创新点

1. **多模态融合**：语音、文字、视觉（数字人）三模态无缝融合
2. **景区专属RAG**：精准检索景区知识，大幅提升准确率
3. **GPS智能联动**：位置感知自动触发对应景点讲解
4. **情感闭环优化**：实时情感监测，自动优化服务质量
5. **三端协同设计**：手机/大屏/管理后台数据实时同步
6. **渐进式降级**：GPU不可用时优雅降级到CSS动画
